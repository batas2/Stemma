# Commercialization — Stemma as a side income

> Status: **working plan, not yet executed**. Written 2026-06-10. Owner: Bartosz.
> Framing: a solo side project run on evenings/weekends from Poland (EU), targeting meaningful
> side income — **not** a venture-scale startup. Every choice below optimizes for low ops burden,
> low legal risk, and reversibility.
>
> Sections marked **🔍 Needs deeper thinking** are decisions that deserve a dedicated session
> before acting; they are consolidated into a checklist at the bottom.

## 1. The one constraint that shapes everything

Stemma's engine compiles the user's C# workspace with MSBuild/Roslyn. Compiling an untrusted
repository **executes arbitrary code by design** (build tasks, analyzers, generators). Therefore:

- **Never** run the modeling engine as a shared multi-tenant cloud service without hard
  per-tenant isolation (Firecracker/gVisor-class). That is venture-scale ops, not side-project ops.
- The editor stays **local-first** (user's machine, user's repos, user's git). This is also the
  product's honest pitch: your model never leaves your repo.
- The **cloud product is the sharing layer**, not the editor. The F-001 HTML report is a static,
  safe, self-contained artifact — hosting it plus a comments API is a small, boring, cheap service.

## 2. Who pays, and for what

| Persona (see [users-and-personas](./users-and-personas.md)) | Pays for | Willingness |
|---|---|---|
| Solo solution/data architect, consultant | Looking professional in front of clients: polished reports, hosted share links, commercial license | Medium-high, personal card / small invoice |
| Architecture lead in a 10–200-dev org | Team visibility: hosted reports per repo, comments that land back in the model, CI freshness | High, but procurement friction |
| Consultancies / software houses (PL/EU market is dense with them) | Per-engagement deliverables; white-label reports | High — a report that replaces a Confluence page is a billable artifact |

The wedge user is the **consultant architect**: they already have the repo locally, they need to
*show* architecture to people who don't run tools, and they expense small SaaS without procurement.

> 🔍 **Needs deeper thinking:** validate this with 5–10 real conversations before Phase 2 pricing.
> Specifically: do consultants want hosted links, or do they prefer the single attachable file
> (which is free)? The answer moves revenue between the license model and the SaaS model.

## 4. Phases, concretely

### Phase 0 — Foundations (target: 2–3 weekends, before anything public)

1. **Name & trademark. — Decided: Stemma.** The previous name collided with a funded German ESG
   SaaS, a well-known publisher, and an active Servo-based browser project on GitHub, and its
   domains were all held by brokers. *Stemma* (a *stemma codicum* is the manuscript family tree
   showing how every copy descends from one archetype) is free across `stemma.dev`, `stemma.io`
   and `stemma.app`, the NuGet id `Stemma` is unregistered, and the GitHub org `stemmahq` is
   available. The only prior software use — a data-catalog startup of that name — was absorbed
   into Teradata in 2023 and no longer trades.
   Remaining: buy `stemma.dev` (~€15/yr), reserve the NuGet id and GitHub org, and run an
   EUIPO/USPTO class 9/42 search to confirm no live word mark survives the acquisition.
2. **License.** Recommended default: **FSL (Functional Source License)** or BSL for the whole
   repo — source-available, free for non-commercial/internal use, converts to Apache-2.0 after
   2 years; sell commercial licenses on top. Alternative: MIT core + closed `Publish` service.
   > 🔍 **Needs deeper thinking:** FSL vs BSL vs MIT-core split — affects community goodwill,
   > contribution policy, and whether competitors can host your sharing layer. One evening of
   > reading + a written ADR-style decision in this folder.
3. **Legal/tax rails (Poland).** Side income needs an invoice path: JDG (działalność) or selling
   exclusively through a **Merchant of Record (Lemon Squeezy / Paddle)** which handles EU VAT,
   OSS/MOSS, and invoices — strongly recommended; MoR fee (~5% + payment costs) is the price of
   not doing VAT compliance evenings.
   > 🔍 **Needs deeper thinking:** confirm with an accountant whether MoR income still requires
   > JDG registration / which PIT form; 1 hour with a księgowa, before first sale, not after.
4. **Distribution.** `dotnet tool install -g <name>` + a Docker one-liner; `--prod` build already
   exists (`run.sh`). Add a first-run "open browser" and a version-check ping (opt-in).
5. **Landing page + demo.** One page: 60-second screen capture (canvas edit → `git diff` → HTML
   report), the one-liner ("the diagram is your code — and it round-trips"), email capture.
   Host on Cloudflare Pages (free).
6. **Report watermark.** Footer link "Made with <name>" in every exported report (already trivially
   addable in `template.ts`) — each shared report is an ad. Paid tiers can remove it later.
7. **Telemetry, opt-in.** Anonymous counters only (exports, views used). You cannot price what you
   cannot see being used.

**Exit criteria:** name owned, license file committed, tool installable in one command, landing
page live.

### Phase 1 — Audience (4–8 weeks, parallel with normal life)

1. Ship publicly: Show HN, r/ExperiencedDevs, r/softwarearchitecture, LinkedIn (your own network —
   PL architecture/consulting scene is exactly the wedge persona), C4/Structurizr community spaces
   (position as *adjacent*: "Structurizr models live in a DSL; Stemma's model **is** the compiling C#").
2. Content that demonstrates, not argues: 3 short posts/videos — "diagram that survives a
   refactor", "architecture report your CFO can open", "comments that come back into the repo".
3. Collect: GitHub stars are vanity; **emails and report exports are the metric**. Target before
   Phase 2: **20 external users, 5 conversations, 3 people who say they'd pay**.

**Exit criteria:** the 20/5/3 numbers above — or a documented decision to pivot the wedge.

### Phase 2 — First revenue (commercial license, then Publish MVP)

**2a. Commercial license (1 weekend once Phase 0 done).**
- Lemon Squeezy product: "Commercial license, €119/yr per seat" (anchor; adjust after 5 sales).
- Free for personal/evaluation. Honor-system enforcement at first (a license field in settings, no
  hard DRM) — consultants pay for legitimacy, not because of locks.

**2b. "Publish" SaaS MVP (3–6 weekends).**
- Scope, deliberately tiny: `<name> publish` CLI/command → uploads the already-generated report →
  `app.<name>.dev/r/<id>` behind a share link (unlisted / password / email-gated); report version
  history; **server-side comments** on the hosted report (same `CommentsSidecar` schema, synced
  back via the existing comment-pack import or `pull-comments` command).
- Stack for one person: Cloudflare Pages/Workers + R2 (report files) + D1/Turso (comments, users,
  links) + Lemon Squeezy webhooks for entitlements. Runs in free/cheap tiers until real traction;
  ops budget < €20/mo.
- Pricing sketch: Free = single-file export (forever). **Solo €12/mo** = hosted reports, link
  access control, comments, no watermark. **Team €49/mo** = 5 seats, shared spaces, comment→repo
  sync. Annual = 2 months off.
  > 🔍 **Needs deeper thinking:** GDPR surface appears exactly here (accounts, comments with
  > names/emails, EU hosting choice, DPA boilerplate, privacy policy). Half-day task with
  > templates; do it before the first non-friend user, not after.
  > 🔍 **Needs deeper thinking:** report access control model (unlisted link vs magic-link email
  > vs SSO) — drives most of the backend complexity; pick the simplest that consultants accept.

**Side-income math (sanity check, guesses to refine with real data):**
- Target ~€1 000/mo: ≈ 25 Solo subs + a handful of licenses, or 12 Solo + 8 Team... realistic
  within 12–18 months *if* Phase 1 metrics are hit; not automatic.
- Target ~€3 000/mo: needs the GitHub App / team motion (Phase 3) — treat as year-2 question.

### Phase 3 — Team wedge (only after recurring revenue exists)

- **GitHub App**: connect repo → CI regenerates the report on merge → hosted + "architecture
  changed" PR comment with a model diff; report comments sync back as PR comments/issues.
  Subscription per org. This is the durable B2B product and the first thing that justifies more
  serious infra.
- Cloud *editing* stays out of scope until this app produces enough to pay for proper isolation
  work (see §1). Revisit only with revenue.
  > 🔍 **Needs deeper thinking:** model-diff quality (F-001 Q7-B baseline diff) becomes the core
  > feature here — needs its own feature record before Phase 3 starts.

## 6. Risks & kill criteria

- **No pull**: if after Phase 1 the 20/5/3 metrics aren't met by a self-set date (suggest:
  3 months after public ship), stop monetization work; keep Stemma as a portfolio piece.
- **Time creep**: any phase exceeding 2× its estimate gets re-scoped in this file, not silently.
- **Security incident on Publish**: keep scope static-files+comments; never accept executable
  content; reports are sanitized at *generation* (already true) — re-verify on upload.
- **Single-vendor risks**: Lemon Squeezy/Cloudflare are replaceable by design (static files +
  SQLite-shaped data); avoid features that lock into either.
- **Day-job conflict**: check employment contract IP/non-compete clauses **before** first sale.
  > 🔍 **Needs deeper thinking:** this one is personal-legal; resolve early, quietly, definitively.
